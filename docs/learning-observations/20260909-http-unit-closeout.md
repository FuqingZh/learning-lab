## 实际观察到的应用与修正

视频转码迁移情境中，用户主动将总任务、子任务、数据库、文件与 Worker 状态联系起来，
提出通过查询推进恢复。这是可见的应用行为，但回答仍混淆了 POST/GET 与任务生命周期，
并将客户端收到成功确认纳入后台完成条件。随后教师解释：保留已发布的子任务结果，
恢复未完成部分；结果的正式发布与客户端获知是不同事实。

用户追问执行资格、数据库作为资格裁决点、同时查看与修改的物理过程，以及完全同时
竞争时如何决定胜者。教师解释了 PostgreSQL Read Committed 的冲突等待与条件重查，
并区分 SQLite 的单写事务、底层原子操作、不可预测的竞争结果与随机选择。
这些追问和后续讲解不能视为独立 SQL 实现、保留效果或已掌握的证明。
