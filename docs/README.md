# Learning Lab Documentation

This directory contains durable design and execution guidance for the learning
workspace. Personal mastery evidence remains under `learning-records/`; these
documents describe the workspace itself rather than claiming product authority
for any source repository.

## Read first

- [Knowledge map implementation plan](implementation-plans/20260820-v1.0-knowledge-map-implementation-plan.md):
  active plan for the concept graph, repository views, generated frontend, and
  Obsidian compatibility.
- [Ambient Learning implementation plan](implementation-plans/20260821-v1.1-ambient-learning-implementation-plan.md):
  active plan for interruption-safe lesson units, concept-level evidence,
  review scheduling, the tutor skill, and the generated learning views.
- [Evidence-backed knowledge history implementation plan](implementation-plans/20260824-v1.2-evidence-backed-knowledge-history-plan.md):
  active plan for audited historical dossiers, their teaching boundary, and
  their separate generated projection.
- [TypeScript explorer and evidence graph implementation plan](implementation-plans/20260824-v1.3-typescript-explorer-and-evidence-graph-plan.md):
  active delivery record for the strict TypeScript frontend and explicit
  claim-to-concept, claim-to-source evidence network.
- [Mission-led learning loop implementation plan](implementation-plans/20260827-v1.4-mission-led-learning-loop-implementation-plan.md):
  delivery record for learner-contract binding, reviewed capability ownership,
  review-cue semantics, structured resume, frontend reconciliation, and the
  bounded behavioral-evaluation contract.
- [Add or update a knowledge concept](how-to-guides/20260820-v1.0-add-knowledge-concept-how-to-guide.md):
  authoring, evidence-linking, generation, validation, and recovery procedure.
- [Add or update an evidence-backed history dossier](how-to-guides/20260824-v1.2-add-evidence-backed-history-how-to-guide.md):
  source review, uncertainty handling, authoring, validation, and recovery.

The [2026-08-27 learning-method review](reviews/20260827-v1.0-learning-method-review.md)
is observational. It does not replace `MISSION.md`, `NOTES.md`, demonstrated
learning records, either track curriculum, or runtime schemas. Its accepted
follow-up is routed through the v1.4 plan above.

## Audits and evaluation

- [Learning-record legacy audit](audits/20260827-learning-record-audit.md):
  all 37 legacy records accounted for without filename inference.
- [Canonical terminology audit](audits/20260827-terminology-audit.md):
  all 33 former glossary labels resolved against the two-source gate.
- [Repository vocabulary](reference/repository-vocabulary.md): useful
  descriptive phrases deliberately kept outside the canonical glossary.
- [Tutor evaluation contract](evaluations/README.md): six synthetic cases,
  deterministic state replay, scorecard provenance, and the explicit boundary
  between structural verification and model-backed reliability.
- [Tutor evaluation status](evaluations/20260827-tutor-evaluation-status.md):
  static gate result and the still-incomplete model-backed boundary.

There is no separate architecture document or testing standard yet. The active
implementation plans own the knowledge-map, ambient-learning, and history
boundaries and verification contracts until those formats are stable enough to
promote into architecture and testing documents. They do not override the
personal learning mission, teaching preferences, or reviewed learner
capability.

## Recorded reviews

[reviews/](reviews/) holds dated assessments of the workspace learning method
and tutor loop. They are not current design authority. Generated maps, session
state, and the tutor skill remain governed by the plans above.
