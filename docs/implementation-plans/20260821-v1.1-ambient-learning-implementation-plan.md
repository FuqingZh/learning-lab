# v1.1 Ambient Learning implementation plan

## Outcome

Turn the existing knowledge map into a low-friction, interruption-safe learning
loop. A learner can ask to continue for three minutes, receive one coherent
knowledge increment, make at most one unaided retrieval or transfer attempt,
and stop while the repository records evidence and schedules the next useful
encounter.

The knowledge map remains the source of conceptual structure. Learning events
become the source of personal capability and review state. The generated site
is a projection of both contracts, not a second source of truth.

## Non-goals for v1.1

- Do not implement a general course-authoring platform.
- Do not require Anki, Obsidian, a database, or a network service.
- Do not claim that a fixed review interval is scientifically optimal.
- Do not infer durable retention from a legacy `*-mastered.md` filename.
- Do not automatically promote explanatory phrases into canonical concepts.
- Do not turn every interaction into a quiz or require a long assessment.

## Invariants

1. One learning session advances at most one coherent capability increment.
2. A session may cite several concepts, but evidence is recorded per concept.
3. `capability_state` and `review_state` are separate dimensions.
4. A `retained` state requires delayed, unassisted transfer evidence.
5. Missing or ambiguous evidence fails closed and never becomes `retained`.
6. The learner may stop at any point; the exact resume point remains durable.
7. Canonical terms continue to satisfy the repository terminology gate.
8. All generated data is stable, repository-relative, JSON-compatible, and
   deterministically ordered.

## Source contracts

### Session events

Append-only session events live under `learning-state/sessions/` as YAML. The
filename is the event `id` plus `.yaml`. Required v1 fields are:

```yaml
schema_version: 1
id: 20260821T123000+0800-idempotency-recall
started_at: 2026-08-21T12:30:00+08:00
duration_minutes: 3
mode: contextual-review
track: scientific-ai-platforms
resume:
  from: idempotency
  next: partial-failure
  summary: 请求超时不能证明操作失败；下次继续判断如何恢复权威状态。
evidence:
  - concept: idempotency
    check: fresh-case-transfer
    outcome: pass
    confidence: medium
    assisted: false
```

Allowed `mode` values are `guided-lesson`, `contextual-review`,
`real-work-application`, and `consolidation`. Allowed checks are `exposure`,
`explain-back`, `boundary-decision`, `fresh-case-transfer`, and
`real-work-application`. Outcomes are `pass`, `partial`, and `miss`.
Confidence is `low`, `medium`, or `high`.

The event loader rejects duplicate YAML keys, unknown concepts or tracks,
invalid timestamps, duplicate concept evidence within one event, impossible
durations, and non-JSON extension values.

### Derived learning state

`scripts/build-learning-state.py normalized-data` consumes the validated
knowledge graph and session events. It emits:

```json
{
  "schema_version": 1,
  "scheduler": {"id": "fixed-v1", "pass_intervals_days": [1, 7, 21, 60]},
  "concepts": [{
    "id": "idempotency",
    "capability_state": "usable",
    "review_state": "scheduled",
    "last_reviewed": "2026-08-21T12:30:00+08:00",
    "next_review": "2026-08-22",
    "evidence_count": 1,
    "latest_outcome": "pass"
  }],
  "resume": {
    "event_id": "20260821T123000+0800-idempotency-recall",
    "track": "scientific-ai-platforms",
    "from": "idempotency",
    "next": "partial-failure",
    "summary": "..."
  }
}
```

Canonical normalized data does not depend on the current clock. `review_state`
is `unassessed` when there is no evidence and `scheduled` when `next_review`
exists. `list-due --today YYYY-MM-DD` projects `due` at the caller boundary.
The browser computes the same view from its local date.

### Capability derivation

- A passing `exposure` establishes `encountered`.
- A passing `explain-back` or `boundary-decision` establishes `familiar`.
- A passing `fresh-case-transfer` or `real-work-application` establishes
  `usable`.
- `retained` requires a later unassisted passing transfer or real-work event at
  least seven calendar days after an earlier passing event for that concept.
- `partial` and `miss` never upgrade capability. They shorten the next review
  interval and set the due projection to `lapsed` when it is current.
- Legacy record mastery stays visible in the existing graph but does not, by
  itself, establish v1.1 capability state.

### fixed-v1 scheduling

Successful encounters use intervals of 1, 7, 21, and 60 days according to the
number of successful events, capped at 60 days. `partial` and `miss` schedule a
review for the next day. This named policy is transparent and replaceable; a
future FSRS adapter must consume the same event history without changing source
events.

## Tutor skill contract

The repo-local skill lives at `.agents/skills/learning-lab-tutor/` and follows
this selection order:

1. due, important prior knowledge;
2. a concept naturally triggered by the current repository task;
3. a blocking prerequisite on the active track;
4. the next small step in the active track;
5. a foundational node that has remained unassessed.

The default session is three minutes. It begins with at most two short resume
sentences, teaches one coherent increment, asks at most one retrieval or
transfer prompt, records the observed evidence, and stops. It never exposes an
answer before a due retrieval attempt, manufactures a streak, or requires the
learner to maintain scheduling files manually.

## Site projection

The generated self-contained site embeds the canonical graph plus normalized
learning state. Add:

- a `Today` view for due concepts;
- a `Continue` view for the latest resume point;
- a `Recall` control that hides definitions and adjacent relationships until
  reveal;
- capability and next-review information in the concept panel;
- a three-minute entry card ahead of the full graph.

Global, track, case-lab, and focal graph views remain available. Empty learning
state must render as a calm onboarding state rather than an error.

## Terminology migration

Add structured terminology provenance only after an exact-label audit. Each
canonical term requires a preferred English term, a check date, and at least
two independent authoritative sources. Structural validation can verify the
shape and source independence; semantic community adoption remains a review
decision. Uncorroborated labels are renamed, represented as aliases, or demoted
to lesson prose rather than assigned fabricated citations.

## Delivery slices

### Slice 1: idempotency three-minute vertical path

- Implement the event validator, normalized state, due CLI, and tests.
- Seed one evidence-bearing pilot event from the existing idempotency learning
  record without claiming delayed retention.
- Implement the tutor skill and restart-safe resume behavior.
- Render Today, Continue, Recall, capability, and next-review UI.
- Keep the existing graph and generated Markdown byte-stable except for
  intentionally documented additions.

### Slice 2: concept evidence and terminology

- Audit all existing canonical labels against the terminology gate.
- Add structured terminology metadata and validation.
- Replace broad record-derived learning claims with explicit concept evidence.

### Slice 3: adaptive scheduling and clients

- Evaluate fixed-v1 using real review history before adopting FSRS.
- Add an adapter for Obsidian review plugins without changing canonical source
  files.
- Publish the regenerated self-contained site through the existing GitHub Pages
  workflow.

## Verification

The canonical gate is `bash scripts/check-structure.sh`. Focused checks cover:

- duplicate-key and schema rejection for session YAML;
- deterministic normalized state across subprocesses;
- due projection for explicit dates;
- retained-state delayed-evidence boundary;
- site embedded graph and learning-state equality;
- browser execution of Today, Continue, Recall, empty-state, and source links;
- repo-local skill structure and deterministic helper scripts;
- generated artifact drift and `git diff --check`.

Completion requires fresh readback from the generated `site/index.html` and no
modification to pre-existing unrelated learner worktree changes.
