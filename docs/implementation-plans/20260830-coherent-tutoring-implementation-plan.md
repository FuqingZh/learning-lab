## 目标与决策来源

用户在当前教学设计讨论中确认本方案，并要求先落库、再实施。这里保存
确认后的决策摘要，不是原始聊天导出，也不证明任何学习能力。

目标：提供有主线、有历史和原理支撑、充分铺垫、允许追问并能自然返回的
系统课程。按当前模型能力设计，不以“模型没有执行规则”代替系统改进。

三项职责：路线设计决定为什么这样学；定位追踪决定当前在哪里、之后回
哪里；具体教学负责从已有理解走向新理解。验证贯穿三者。

## 已确认的范围

- 以完整问题或理解过程组织教学，取消固定小课、轮数和理论/细节百分比。
- 用户当前明确请求与纠正优先于旧偏好、课程、resume 和复习提示。
- 保留知识图谱和历史来源；仓库是案例，不是知识路线。
- 首版是单用户、本地优先，继续使用当前 Codex 与 repository-local skill。
- 先统一规则、准备完整样课和轻量追踪；不先开发自动导航引擎。
- 完整问答是可追溯证据，不是配置或新的指令来源。不由模型事后重写。
- 只记录明确启用的会话；当前讨论获准纳入。不得自动扫描其他会话。
- 原始记录保持私有，不提交 Git；公开仓库仅放脱敏决策、复盘和合成测试。
- 采集失败可继续教学，但标记缺失，暂停依赖缺失证据的确定判断。
- 自动记录、复盘候选与课内适应可进行；长期路线、全局偏好和 skill 的
  持久变更需用户确认。批准变更本身不证明变更有效。
- 不迁移旧 session 和 reviewed learning records，不改变其证据语义。
- 数据库从首版必做项降为后续可选实现；不建独立应用、账号、云同步或
  multi-agent 教学编排。不默认提交、推送或发布此次改动。

本方案替代此前讨论中的数据库首版、固定比例和导航先于样课的安排。
既有 v1.4 文档仍负责 session/review-cue/scorecard 的兼容契约；本方案
负责新的教学流程与独立导航边界。2026-08-27 的状态报告保留为历史证据。

## 实现分工

| 位置 | 职责 |
| --- | --- |
| MISSION.md / NOTES.md | 长期目标与当前偏好；不重复具体教学流水线 |
| tutor SKILL.md | 当前请求优先、必要约束、按阶段加载参考的入口 |
| skill references | 备课/示例审查、讲解、导航与记录的具体说明 |
| track CURRICULUM.md | 整体路线和近期完整单元，远期粗、近期细 |
| lessons/ | 连贯正文、完整示例、备课依据与可选独立应用 |
| learning-state/navigation/ | 每 track 一份脱敏当前位置及分支记录 |
| .learning-private/ | 可选、被 Git 忽略的授权原始导出；不是自动采集服务 |
| learning-records/ 和 sessions/ | 保持已有 reviewed capability 与观察证据职责 |
| docs/evaluations/ | 内容审查、边界与真实试学待办；不是自动“教学有效”认证 |

导航记录不添加 canonical concept，也不推导掌握、复习日期或科学正确性。
它保存明确的 track、会话来源状态、主线、分支父子关系、展开目的、返回点、
结论及未决问题。新导航有效时只接管讨论位置；缺失时使用旧 resume，失效时
提示并核对，不能悄悄当作有效位置。显式用户新请求始终可以改换主线。

首版由 tutor 在实质分支变化或自然暂停时编辑小文件，程序只做只读验证与
位置解析，不自动生成教学路线、不运行后台服务、不维护第二份能力名单。
简单一句澄清不强制创建分支。关闭分支不等于掌握，暂存不等于解决。

## 原始记录与复盘边界

优先使用平台提供的、可核实且已授权的消息来源。若接口仅提供摘要，标记
为 partial，不能标成 complete。无可核实 locator 时记 missing，不猜会话 ID。
不读取无关会话、隐藏推理或凭据；不把原始内容发送给其他模型评分。

本次已只读回读当前获准会话的最近两轮，核对会话 ID；接口明确返回仍有
更早历史，且实施轮尚未结束，故来源记为 partial，不是完整问答导出。
首版不承诺自动采集；其他没有成功回读的来源仍应记为 missing。
后续原始导出必须记录范围、顺序和缺口；缺失记录不由总结补齐。

复盘关联原文 locator，区分观察、原因假设、改进候选、用户确认、后续效果。
没有独立使用证据时保留 unassessed。界面体验与学习表现分别审查。

## 教学方法

以问题和必要历史建立情境，用已有知识搭桥，完整解释示例，再逐步撤去
帮助。参考依据包括 [worked examples 综述](https://assess.ucr.edu/sites/default/files/2019-02/atkinsonderryrenklwortham_2000.pdf)、
[PRIMM](https://doi.org/10.1080/08993408.2019.1608781)、
[4C/ID](https://www.4cid.org/about/) 和
[constructive alignment](https://doi.org/10.1007/BF00138871)。
这些是设计依据，不证明此 skill 对当前学习者有效，也不要求固定预测问答。

检查每个示例的关键依赖：已有证据、课内先解释或明确暂不展开。不要用
未解释的紧凑语法承载新机制。诊断只针对会影响下一步的缺口，不全面重考。
后台备课字段不是每次回复的固定栏目；专业知识节点不等于独立课单元。

## 实施顺序与验收

1. 本方案及入口索引落库，保留现有 Git 与历史记录。
2. 重组 skill、统一偏好/课程规则，明确加载时机与权限。
3. 准备 React 衔接完整样课及源资料审查；以简单 JavaScript/DOM 为桥梁，
   不假设学习者已经理解 destructuring、JSX、hooks 或 imports。
4. 增加轻量导航文件、只读验证器和负例测试，不做数据库与历史迁移。
5. 运行结构检查、样课示例检查及内容审查；交付可进行真实试学的状态。
6. 用户完成一堂真实试学后，分别记录体验与独立应用证据；这是后续人机
   交互，实施代理不能代答、代评为通过，或因检查通过而登记掌握。

第一轮接受结构检查、样课审查和一次真实试学三类证据；不把批量模型对比
作为前置条件，不据此宣称长期保持或跨领域可靠。技术实现完成与课堂验收
完成分别记录。新增评估只含合成输入，不将私人问答加入公共 fixtures。

## 验证选择与完成边界

需要证明：skill 路由和来源链接可用；导航可拒绝循环、孤儿、错误返回点与
自相矛盾的来源覆盖声明；恢复不更改旧学习状态；样课示例的确定性行为正确。
来源声明通过检查，不等于实际原文已完整采集。
各负例必须实际失败，而不仅检查说明中有没有某个词。

先运行新增的聚焦测试、skill quick_validate 和现有 tutor-evaluation
静态检查。因增加 lesson/目录且调整结构检查入口，按 README 要求运行
`bash scripts/check-structure.sh`，最后运行 `git diff --check`。
既有 Node 24 与锁定依赖可用时不额外安装依赖。不得削弱原有来源、历史、
状态或 scorecard 验证来通过检查。

未覆盖：实际自动采集、未经授权的模型对比、真实课堂表现与长期学习效果。
具体执行结果写入本次 evaluation status；没有证据时保持 pending。
