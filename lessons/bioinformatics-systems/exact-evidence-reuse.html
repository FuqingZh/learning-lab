第 1 课：何时可以复用序列注释

SeqEvi 学习轨道 · 基础能力 1

目标：看到两个注释请求时，能判断应当复用、重新计算，还是不能缓存，并指出 EvidenceKey 的变化。

1. 先拆开三个对象

  1. 输入记录：FASTA 中的一条记录，有本次调用的标题和 InputID。
  2. 蛋白序列：规范化后的氨基酸内容；不同标题可以指向同一序列。
  3. 注释证据：明确工具环境用明确数据库和参数解释该序列所得的结果。

序列相同只回答被研究对象相同，没有回答研究方法和知识库相同。

2. 从字符到 SequenceID

SeqEvi 去除 ASCII 空白、转大写、移除至多一个末端星号，再验证字符。规范序列的 ASCII 字节经 SHA-512/24 和 URL-safe Base64 编码，形成 SQ. 标识。

输入规范化身份
sample_A: mkwv tfisll*MKWVTFISLL相同 SequenceID
customer_982: MKWVTFISLLMKWVTFISLL

标题只属于调用映射，不进入共享序列表；项目号、客户名和 accession 不会冒充内容身份。

3. 完整 EvidenceKey

EvidenceKey = (
    SequenceID,
    AdapterContractVersion,
    ToolRuntimeDigest,
    ResourceID,
    SemanticParameters,
)
  • SequenceID：研究哪条规范蛋白序列。
  • AdapterContractVersion：SeqEvi 如何调用、解析、关联和解释结果。
  • ToolRuntimeDigest：实际执行环境的不可变身份，而不只是版本字符串。
  • ResourceID：实际注释数据库的不可变身份。
  • SemanticParameters：全部会改变科学结果的参数，包括显式默认值。
校准：同一序列加相同工具版本仍不足以复用。数据库、语义参数或适配器解释规则任一变化，都是另一份合法证据。

4. “只做一次”的精确定义

对一个完整且完全相同的 EvidenceKey，只需保存一个不可变终态；未来映射到该 key 的输入记录都可复用。

hit 与成功的 no_hit 都是可缓存终态。失败、超时、损坏输出或适配器拒绝不是可复用证据。

线程数、临时目录和日志级别若不改变科学语义，属于运行方式，不改变 key；E-value、taxonomy scope、搜索模式和数据库内容会改变 key。

5. 逻辑一次与物理一次

EvidenceKey 回答结果是否等价；并发协调回答两个进程会不会同时浪费计算。唯一约束可以保证最终只有一份权威记录，但两个客户端仍可能同时观察到 miss。claim/lease 用于减少重复执行，不属于科学身份。

6. InputID 如何取回结果

多个 InputID 可 many-to-one 映射到同一 SequenceID，再由 SequenceID 关联证据。这样既全局去重，又能按本次输入的 ID 和顺序交付结果。

无提示检索练习

  1. FASTA 标题不同；规范序列和其余 key 全相同。
  2. 序列与 eggNOG-mapper 版本相同，但数据库升级。
  3. 所有 key 相同，上一次成功结束但没有命中。
  4. 所有 key 相同，上一次超时退出。
  5. 所有内容相同，只把线程数从 8 改为 64，且上游保证不改变科学结果。

分别回答“复用、重新计算或不能缓存”，并指出理由。
