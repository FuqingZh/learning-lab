# 从 React 到 PostgreSQL 的完整任务流程

## 单元主线

接续 [HTTP 与 FastAPI](http-boundary-and-fastapi.md)，把一项操作从页面事件追踪到
服务端验证、数据库提交、独立 Worker 和查询展示。它是原技术路线第 9 阶段，
不要求先穷尽框架内部机制，也不把讲解覆盖视为独立掌握。

当前位置由 `python3 scripts/check-teaching-navigation.py resolve --track scientific-ai-platforms`
给出。本文件保存组织框架，不再维护第二个实时检查点。

## 实践范围

第一步只完成一份演示报告：React 提交确定的名称和操作编号；FastAPI 校验输入，
PostgreSQL 保存任务并提交；Worker 领取、续期并保存演示文本；页面查询同一任务。
不接真实模型或科研数据，不把本地示例直接作为多用户生产服务。

[标准库与 SQLite 实验](task-demo/README.md)是此前的脚手架。正式技术栈实践需要
重新验证 PostgreSQL 的条件领取和独立进程恢复，不能照搬 SQLite 测试结论。

## 阅读与操作顺序

1. 先运行完整流程，识别浏览器、API、数据库和 Worker 四个执行位置。
2. 沿提交事件定位 HTTP 请求、模型验证、业务函数、事务提交与返回。
3. 用数据库记录和 Worker 输出核对领取、执行与完成，不依赖页面猜测。
4. 暂停查询、停止 Worker、重复提交同一操作，观察分别影响哪条生命周期。
5. 在指导下改动一个明确行为；随后用新情境检查独立应用。

## 验证与边界

应验证同键同内容返回同一任务、同键异内容拒绝、提交失败不回复已接受，
两个 PostgreSQL 连接竞争只产生一个有效领取，Worker 中断后可接手且旧代次不能发布，
查询失败不改写后台任务失败，过时响应不能覆盖当前任务。

先为示例声明执行和恢复预算，显式保留无法确认的结果。测试代码与教师操作
只能证明所检查的实现行为；权限、取消、真实外部文件及科研正确性分别验证。
