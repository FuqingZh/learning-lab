# Route and lesson preparation

Read before selecting a unit or revising the near-term route. This is a
teacher's preparation guide, not the learner-facing answer template.

## Select from evidence

Start with the current request and confirmed mission. Use relevant reviewed
capability records to judge prerequisites, then the stage curriculum, valid
navigation/legacy resume, and advisory review cues. A broad label such as
`program` does not establish fluency in destructuring or React. When evidence
is absent, use a small relevant diagnostic only if it changes the next
explanation; otherwise bridge the prerequisite in context. Do not impose an
entry exam or re-test everything the learner already demonstrated.

Keep stage outcomes broad; prepare only the current and near-next connected
units in detail. Organize by problems/capabilities, not compulsory glossary
nodes. The map and history inform the route but do not force exhaustive coverage.

## Prepare a usable unit

In the lesson's preparation notes identify the complete question, the desired
explanation/application, prerequisite evidence and unknowns, the complete
example and its syntax, deferred details, sources and their limits, a matched
independent task, and the connection to the larger route.

The lesson can span replies. Not every reply needs history, a diagram, a
counterexample and a quiz. An exercise must test the intended capability, not
incidental API spelling. Do not disclose an assessment answer before an actual
retrieval attempt; examples used for teaching should be fully explained.

## History and source review

For a useful historical increment, read the complete matching dossier under
`histories/` and its linked source before teaching. Explain documented
conditions, problem, proposal and limits; do not invent motive, dialogue or
priority. Chronology is not causality. If evidence is incomplete, omit or bound
the historical claim. Do not infer date-memory mastery or change the session
schema. Recheck canonical entries against AGENTS.md before teaching them as
established terms. Local descriptions can remain lesson prose without promotion.
Current APIs need current primary documentation, not only historical examples.

## Revise proportionally

Repair local gaps within the unit. If a gap changes the stage goal or sustained
route, propose the change with evidence and obtain confirmation. A single
struggle is not a fixed learner trait. Choose depth from current needs, not a
theory/syntax quota or presumed learning-style category.
